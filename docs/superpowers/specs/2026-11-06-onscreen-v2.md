# OnScreen V2

Implement the user's approved continuation on `onscreen/test-mode-hardening` (PR #6). Railway Development only. Never merge or deploy production.

Keep Express, Socket.IO and Railway PostgreSQL. Use Supabase Auth for Google and email/password; verify access tokens server-side and scope every professor record to the verified user ID. Students need no account. Fail closed when storage or authentication configuration is missing.

Launch, Library and Results form the private workspace. Library tests persist and remain editable; launches take immutable snapshots. Tests launch into a waiting room with a separate Start control. Calculator mode remains available. A separate popup uses an unguessable display capability and receives names/status only, never IDs, numbers, scores, answer keys or incidents. Its QR expands on click. Provide a popup-blocker fallback.

Student joins require student number (text, preserve leading zeros) and name. Issue a private resume capability; persist enrollment, drafts, submissions and incidents. Professor/browser disconnection never ends an exam. Database restart recovery must retain sessions. One final submission per enrollment, graded on the server, with immediate own score and percentage, no answer key.

After a test starts, confirmed continuous page-hidden time strictly greater than 5000 ms causes a durable FAIL and effective score zero. Network loss alone marks red but does not fail. Waiting and submitted students do not acquire new failures. A failure remains red on return. Record raw score and an audit trail; professor can override with a reason. Override restores the raw score and current visibility status. Public display contains names/status only.

Results persist per professor. Excel export sorts student numbers naturally, uses exactly student number, student name, absolute score, percentage columns, preserves text identifiers and uses effective scores. Unsubmitted scores are blank unless failed (zero).

Future roadmap only: pasted-text AI multiple-choice generation with professor review. No generation endpoint or AI dependency.

Implementation choices: versioned V2 tables preserve legacy rows without assigning old exams to arbitrary accounts; legacy ownership migration is an explicit later administrative operation. One Railway Development app replica initially; PostgreSQL transactions serialize all session writes. Auth setup and live Railway verification depend on connected credentials/configuration.
