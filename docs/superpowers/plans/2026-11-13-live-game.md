# Live Game Implementation Plan
> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox syntax.
**Goal:** Integrated competitive game mode isolated from academic tests.
**Architecture:** Separate game domain, storage and API modules; reuse professor identity and shared database/socket server. Dedicated game library, host/display/player pages.
**Tech Stack:** Express, PostgreSQL JSONB, Socket.IO, vanilla JS.
**Spec:** docs/superpowers/specs/2026-11-13-live-game-design.md
## Global Constraints
No publication/deployment; separate library and no saved reports; score/recovery server-authoritative.
## Review Focus
- Duplicate answers/retries cannot award twice.
- Wrong-owner requests and forged resume tokens rejected.
- Current question only, keys hidden until reveal.
- Disconnect/restart cannot lose earned score or restart deadline.
- Cleanup/account deletion removes temporary state.
## Tasks
1. Domain/store: write failing tests for scoring, phases, resume, copy and persistence; implement game.js/game-store.js; run focused tests.
2. API: write failing HTTP/socket tests for ownership, public views, joins, answers, recovery; implement game-routes.js and minimal server/store wiring; rerun.
3. UI: add Games navigation, library/editor/copy flow, host/display/player views. Test DOM and build; exercise browser if supported.
4. Integrate: full test suite, build/check, independent review, fix findings and commit locally. Report any browser verification limits.
